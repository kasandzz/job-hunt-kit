# Stage 6: Online backup and morning reminder

## Goal
Give the notebook a private online copy in the user's own name, so nothing is lost if the computer breaks, and set up how the morning check-in reaches them each day. The user should feel safe, not tested: one click per box, and Kas can always finish a piece that gets stuck.

## Steps
Before you start: read `playbook/state/profile.json` (`name`, `language`, `email`), `playbook/state/connectors.md`, `playbook/state/timezone.md` and `playbook/state/helper.json` (if it is missing, treat it as `{"helper_github":"","phone_routine":"disabled"}`).
Rules for this stage:
- Never run `git add .`, `git add -A`, `git add --all` or `git commit -a`. Only ever name files one by one.
- Never delete anything, never force anything, never make the online copy public.
- Words for the user: "online backup" ("respaldo en línea"), "your GitHub account" is fine to say because they see that name on screen. Never say repo, commit or push to them.
- Before any step that runs a program, say in one line: "A box may pop up asking if I can do this. Please click Allow." (es-MX: "Puede salir un aviso pidiendo permiso. Dale clic en Permitir.")
- Their online copy is called `my-life` (es-MX: `mi-vida`). Below, `<copy>` means that name.

1. **Explain, in two short sentences.** en-GB: "Next I'll make a private copy of your notebook online, in your name, so nothing is lost if the computer breaks. The copy lives on GitHub, a website that keeps files safe; only you can see yours." es-MX: "Ahora hago una copia privada de tu cuaderno en línea, a tu nombre, para que nada se pierda si la computadora se descompone. La copia vive en GitHub, una página de internet que guarda archivos seguros; solo tú puedes ver la tuya." Then a question box: **Let's do it (Recommended)** / **Not today** / **tell me more** (es-MX **Vamos (Recomendado)** / **Hoy no** / **cuéntame más**). "Not today": write `playbook/state/backup.md` with `backup: skipped <date>`, skip to step 5. Test mode: use the next answer.

2. **GitHub account (their own email).** Open `https://github.com/signup` with `Start-Process "https://github.com/signup"`. Walk them through one click at a time; after each, show a question box with **Done (Recommended)** / **Stuck** / **Explain more**, and the question text says exactly what to do:
   a. en-GB: "A GitHub page opened in your browser. If you already have a GitHub account, click 'Sign in' at the top instead and sign in; then pick Done." es-MX: "Se abrió una página de GitHub en tu navegador. Si ya tienes cuenta de GitHub, dale clic en 'Sign in' arriba y entra; luego elige Listo."
   b. en-GB: "Type your email: `<email from profile.json>`, then click Continue." es-MX: "Escribe tu correo: `<email from profile.json>` y dale clic en Continue."
   c. en-GB: "Choose a password. Write it in your paper notebook, not here. I must never see it. Click Continue." es-MX: "Elige una contraseña. Anótala en tu libreta de papel, no aquí. Yo nunca debo verla. Dale clic en Continue."
   d. en-GB: "Choose a username (for example your name and a number). Click Continue." es-MX: "Elige un nombre de usuario (por ejemplo tu nombre y un número). Dale clic en Continue."
   e. en-GB: "Do the little puzzle. It shows GitHub you're a real person. Then click 'Create account'." es-MX: "Resuelve el pequeño acertijo. Así GitHub sabe que eres una persona de verdad. Luego dale clic en 'Create account'."
   f. en-GB: "GitHub sends you an email with a short code. Open your email, find the code, and type it on the GitHub page." es-MX: "GitHub te manda un correo con un código corto. Abre tu correo, busca el código y escríbelo en la página de GitHub."
   g. en-GB: "If it asks questions about how you'll use it, click 'Skip personalization' at the bottom." es-MX: "Si te hace preguntas sobre cómo lo vas a usar, dale clic en 'Skip personalization' hasta abajo."
   es-MX options: **Listo (Recomendado)** / **Me atoré** / **Explícame más**.
   On **Stuck**: ask what they see (box with 3 likely answers, for example "it says the email is already used" / "I didn't get the code" / "an error message") and guide from there. "Email already used" means they have an account: go to sign in. If they type a password into the chat, do not repeat it or save it anywhere, and remind them kindly to keep it on paper.
   Test mode: do not open anything; log `SKIPPED-TEST 6.2 GitHub sign-up` in `playbook/state/test-log.md`.

3. **Sign in on this computer.** Test mode: log `SKIPPED-TEST 6.3 GitHub sign-in` and skip to step 4.
   a. Find the GitHub helper program: run `where.exe gh`. If nothing is found, check `C:\Program Files\GitHub CLI\gh.exe`. If neither exists, run `winget install --id GitHub.cli --exact --silent --accept-package-agreements --accept-source-agreements`, then use the full path `C:\Program Files\GitHub CLI\gh.exe` (a new install is not on the path until Claude restarts). Below, `gh` means whichever path works.
   b. Run `gh auth status`. If it says "Logged in", go to step 4.
   c. Run `gh auth login --web --hostname github.com --git-protocol https` as a background command, then read its output for the 8-character one-time code (like `ABCD-1234`). Open `https://github.com/login/device` with `Start-Process`. Show a box: en-GB "This lets this computer save to your GitHub copy. On the GitHub page, type this code: **ABCD-1234**. Then click 'Continue' and 'Authorize'." es-MX "Esto deja que esta computadora guarde en tu copia de GitHub. En la página de GitHub, escribe este código: **ABCD-1234**. Luego dale clic en 'Continue' y 'Authorize'." Options: **Done (Recommended)** / **Stuck** / **Explain more** (es-MX **Listo (Recomendado)** / **Me atoré** / **Explícame más**). If no code appears in the output within 30 seconds, stop the background run and use the path in e.
   d. Run `gh auth status` again. When it says "Logged in", run `gh auth setup-git`.
   e. If `gh` will not install after two tries, or sign-in via c does not work: carry on without it. In step 4 use the fallback, and Git Credential Manager shows a GitHub sign-in window on the first upload; tell them to sign in there.

4. **Make the private online copy.** Test mode: log `SKIPPED-TEST 6.4 online copy` and skip to step 5.
   a. Run `git status`. If it says "not a git repository", run `git init` and then `git config core.quotepath false`. Then run `git remote`. If it lists `origin` and `playbook/state/backup.md` does not say `backup: on`, run `git remote rename origin backup-unchecked` now, before anything else, so the automatic backup in c cannot upload to a copy that has not been checked.
   b. Set who the backups belong to, in this notebook only: `git config user.name "<name from profile.json>"` and `git config user.email "<email from profile.json>"`.
   c. **First save, by name only.** The automatic backup that runs at the end of each of your turns saves only files this setup wrote (listed in `playbook/state/session-files.txt`), plus `playbook/progress.md` and the stage done flags. Run it once now: `powershell -NoProfile -ExecutionPolicy Bypass -File .claude/hooks/safe-backup.ps1`. Then add the files the installer placed, which the automatic backup never sees, with `git add -- "<path>" "<path>" ...` (every path named and quoted):
      - `.gitignore`, `.gitattributes`, `.claude/settings.json`, each `.claude/hooks/*.ps1` file, and each `.claude/skills/*/SKILL.md` file (the installer placed the helpers);
      - `.obsidian/community-plugins.json` and each file in `.obsidian/plugins/dataview/`, `.obsidian/plugins/templater-obsidian/` and `.obsidian/plugins/periodic-notes/` (the installer placed the three add-ons), plus `.obsidian/templates.json`, `.obsidian/daily-notes.json` and `.obsidian/core-plugins.json` if they exist;
      - `playbook/PLAYBOOK.md`, `playbook/TROUBLESHOOTING.md`, `playbook/help-bundle.ps1`, `playbook/progress.md`, `playbook/obsidian-tool.md`, `playbook/browser.md`, and each file under `playbook/stages/`, `playbook/profiles/`, `playbook/bundles/`, `playbook/templates/` and `playbook/tools/` (list them with the Glob tool, and add each file by its path). Skip `playbook/state/` entirely: the automatic backup already handles the state files that matter, and some are ignored on purpose;
      - each folder listed in `playbook/state/folders.md` (written in stage 4).
      Then run `git commit -m "auto-backup <yyyy-MM-dd HH:mm>"`. If it says "nothing to commit", that is fine. Run `git log -1 --oneline`: it must show a line; if not, follow the "fails twice" rule in `PLAYBOOK.md`.
   d. **Connect the online copy under a holding name, without uploading.** The automatic backup only uploads to a connection called `origin`. Until the privacy check in e passes, the connection is called `backup-unchecked`, so nothing can be uploaded by accident. Run `git remote`:
      - It lists `origin` (a resumed sitting): go straight to e and check it; on a failed check, rename it as e says.
      - It lists `backup-unchecked` (an earlier try): go to e.
      - Neither, with `gh`: run `gh repo view <copy> --json visibility -q .visibility`.
        - Not found: run `gh repo create <copy> --private --source . --remote backup-unchecked` (no `--push`).
        - Found (made earlier, or an old copy of theirs with the same name): run `gh repo view <copy> --json url -q .url`, then `git remote add backup-unchecked <that url>`. Do not upload yet.
      - Neither, without `gh` (fallback): ask for their GitHub username in a box (they type it under Other). It must match `^[A-Za-z0-9-]{1,39}$` (letters, numbers and dashes, at most 39); if not, ask again kindly and never put it into a command or link. Walk them through `https://github.com/new` with Done/Stuck boxes: "Type `<copy>` as the name", "Click **Private**", "Click the green button at the bottom" (es-MX: "Escribe `<copy>` como nombre", "Dale clic en **Private**", "Dale clic en el botón verde hasta abajo"). Then `git remote add backup-unchecked https://github.com/<username>/<copy>.git`.
   e. **Check it is private, before anything is uploaded. This is a hard stop.**
      - With `gh`: run `gh repo view <copy> --json visibility -q .visibility` (for an existing `origin`, run it with no name). It must print exactly `PRIVATE`.
      - Without `gh`: use whichever connection `git remote` lists (`backup-unchecked`, or `origin` in a resumed sitting); below it is `<conn>`. If you do not have `<username>` from d (a resumed sitting), read it from `git remote get-url <conn>` (`https://github.com/<username>/<copy>.git`) and check it against the same `^[A-Za-z0-9-]{1,39}$` rule; if it does not match, treat it as "the check cannot run". First prove the copy exists and is theirs: run `git ls-remote <conn>` (a GitHub sign-in window may appear; tell them to sign in there). It must finish without an error (exit code 0); if it fails, treat it as "the check cannot run". Only then check anonymously that GitHub does not show it to strangers: `try { (Invoke-WebRequest -UseBasicParsing "https://api.github.com/repos/<username>/<copy>").StatusCode } catch { $_.Exception.Response.StatusCode.value__ }`. It must print `404` (a private copy is invisible to strangers). `200` means it is public.
      - **Pass:** if the connection is still called `backup-unchecked`, run `git remote rename backup-unchecked origin`. Then run `git push -u origin HEAD` (without `gh`, a GitHub sign-in window may appear; tell them to sign in there). It must finish without an error (exit code 0). If it fails, run `git remote rename origin backup-unchecked` and follow the Fail bullet below. Only a successful upload goes on to f.
      - **Fail, or the check cannot run (no internet, an error, anything other than `PRIVATE` / `404`):** make sure nothing is uploaded: if `git remote` lists `origin`, run `git remote rename origin backup-unchecked` (this only renames the connection; no files change). Never make anything public or delete anything. Then make the help file (`playbook/TROUBLESHOOTING.md`, "Making the help file for Kas"), and tell them kindly: en-GB "Your notebook is safe on this computer. One thing online needs Kas to look at it. Please send him the file called <file name> from your Desktop (the main screen of your computer), on WhatsApp." es-MX "Tu cuaderno está seguro en esta computadora. Una cosa en línea la tiene que ver Kas. Mándale por WhatsApp el archivo que se llama <file name>; está en tu Escritorio (la pantalla principal de tu computadora)." Write `backup: needs-kas <date>` to `playbook/state/backup.md` and go to step 5.
   f. All good: write `playbook/state/backup.md` with `backup: on`, `copy: <copy>`, `checked_private: <date>`, `updated: <now>`. Set `updated:` in `progress.md`. Tell them: en-GB "Done. Your notebook now has a private online copy. It updates by itself each time we talk." es-MX "Listo. Tu cuaderno ya tiene una copia privada en línea. Se actualiza solita cada vez que platicamos."

5. **Morning reminder (phone).** Ask the time first, in a question box: en-GB "What time would you like your morning check-in? That's when we say good morning and plan your day." es-MX "¿A qué hora quieres tu plática de buenos días? Es cuando nos saludamos y planeamos tu día." Options: **8:00 (Recommended)** (or a time that fits what they said about their mornings in area 5) / **7:00** / **9:00** / **Another time** (es-MX **8:00 (Recomendado)** / **7:00** / **9:00** / **Otra hora**). Test mode: use the next answer.
   Then read `phone_routine` in `playbook/state/helper.json`.
   - **`phone_routine: enabled` (Kas switches this on; the default is the reminder).** Only when Kas has set it, and only if step 4 finished with `backup: on`:
     a. Install the Claude phone app, with a Done/Stuck box: "On your phone, open the Play Store (Android) or the App Store (iPhone), search for Claude, and install the app by Anthropic. Then sign in with the same account as on this computer." (es-MX: "En tu celular, abre la Play Store (Android) o la App Store (iPhone), busca Claude e instala la app de Anthropic. Luego entra con la misma cuenta que en esta computadora.") Never email the link to them.
     b. Create a cloud routine with them at `https://claude.ai/code/routines`. It must have **no Gmail, Calendar or Drive connection attached**, because the cloud copy runs without this computer's safety blocks. Check that on screen together with a Done/Stuck box ("Under connectors for this routine, is the list empty?") before saving it. The routine runs daily at their time in their time zone, on their online copy `<copy>` (connect GitHub to Claude when it asks), allowed to push only to the branch `claude/checkin` (never `main`). Its instructions must stand alone, because it sees nothing from this computer: "Read CLAUDE.md and .claude/skills/morning-checkin/SKILL.md. Run the morning check-in in <language>. Ask 3 questions: mood, energy, top 3 for today. Save the answers in today's daily note. Save changes only to the claude/checkin branch. Never send email, never delete anything."
     c. Write `playbook/state/phone.md` with `mode: routine`, `time: <HH:MM>`, `timezone: <zone>`, `branch: claude/checkin`, `proof: pending`. The next morning, prove it from the routine's run log at `https://claude.ai/code/routines` (a finished run, and a new save on `claude/checkin`); only then set `proof: <date>`. If the routine cannot be created, or the run log shows no finished run, use the reminder below instead and set `mode: reminder`.
   - **Otherwise (the default): calendar reminder.**
     a. If `calendar: connected` in `connectors.md`, first show the details in a question box: en-GB "I'll put this in your diary: 'Check-in with Claude', every day at <time>, for 10 minutes, with the note 'Open Claude on the computer and say: good morning'. Your phone will remind you. OK?" es-MX "Voy a poner esto en tu agenda: 'Buenos días con Claude', todos los días a las <time>, por 10 minutos, con la nota 'Abre Claude en la computadora y di: buenos días'. Tu celular te va a avisar. ¿Te parece?" Options: **Yes, add it (Recommended)** / **Change the time** / **No reminder** / **tell me more** (es-MX **Sí, agrégalo (Recomendado)** / **Cambiar la hora** / **Sin recordatorio** / **cuéntame más**).
     b. On yes, create one event with `create_event`: daily repeat (`RRULE:FREQ=DAILY`), start at their time tomorrow. en-GB: local time with the time zone from `timezone.md`. es-MX: write the start and end with the fixed offset `-06:00` (for example `2026-10-09T08:00:00-06:00`) and set the time zone to `America/Mexico_City` (no summer time since 2022, so it always matches `-06:00`; a repeating event needs the time zone). Then read it back with `list_events` for tomorrow and check the time is right. If creating it fails, or the time read back is wrong, use the phone alarm in c and record `calendar_event: phone-alarm`.
     c. If Calendar is not connected, or they said no: suggest a daily alarm on their phone at that time with the label "Good morning, Claude" ("Buenos días, Claude"): en-GB "You could set an alarm on your phone for <time> every day, called Good morning, Claude." es-MX "Puedes poner una alarma en tu celular a las <time> todos los días, que se llame Buenos días, Claude."
     d. Write `playbook/state/phone.md` with `mode: reminder`, `time: <HH:MM>`, `timezone: <zone>`, `calendar_event: created` (or `phone-alarm`, or `none`).
   Test mode: never create an event; log `SKIPPED-TEST 6.5 calendar event` and write `phone.md` with `mode: reminder` and `calendar_event: skipped-test`.
   Set `updated:` in `progress.md`.

6. **Finish.** When everything under "Done when" is true, create `playbook/state/stage-6.done` (one line: the date and time), set `current_stage: 7` and `updated: <now, ISO 8601>` in `playbook/progress.md`, and move on to stage 7 in the same sitting unless they typed pause.

## Done when
- `playbook/state/backup.md` exists, and says `backup: on` only after the privacy check printed `PRIVATE` (or `404` without `gh`) before the first upload (or test mode logged `SKIPPED-TEST 6.4`).
- `origin` exists only if the privacy check passed and the first upload succeeded; after a failed check the connection is called `backup-unchecked`.
- No file was added with `git add .`, `-A` or `--all`.
- `playbook/state/phone.md` exists with `mode: routine` or `mode: reminder`.
- `playbook/state/stage-6.done` exists.
